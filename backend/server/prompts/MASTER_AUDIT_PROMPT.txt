DEFINITION: Net Effective Cover (NEC)
NEC = Base Sum Insured
    + Accrued No-Claim Bonus
    + Recharge usable in the same illness

EXCLUDE:
- Conditional restores (e.g., "only for unrelated illness")
- Marketing bonuses
- Benefits not usable in a single hospitalization

PORTING CONTINUITY (CRITICAL — READ BEFORE COMPUTING NEC):
If the policy is ported from another insurer:
- The FULL ported sum insured (original SI carried from previous policy) counts toward NEC.
- Incremental SI added at porting/renewal also counts toward NEC.
- NEC = total current SI + NCB. Do NOT reduce NEC because of incremental SI waiting periods.
- Waiting periods on incremental SI affect CLAIM TIMING, not the NEC calculation.

[PORTING_AND_CONTINUITY_RULES]

PORTING CONTINUITY LAW (IRDAI Portability Regulation):
When a policy is ported from another insurer, the insured carries forward ALL served
waiting periods from the previous policy for the ORIGINAL ported sum insured amount.

RULE 1 — ORIGINAL PORTED SI IS FULLY ACTIVE:
- The base SI carried from the previous policy has ZERO active waiting periods.
- This is non-negotiable under IRDAI regulation.
- DO NOT write any waiting period caveat for the original ported SI anywhere in the output.
- In all summaries, the original SI must be described as "fully active, no waiting periods."

RULE 2 — INCREMENTAL SI AND CONDITION-SPECIFIC WAITING PERIODS:
- If SI was increased at porting or at a subsequent renewal, ONLY the incremental
  amount is subject to fresh waiting periods.
- Incremental amount = Current SI − Original Ported SI.
- The fresh waiting period on the increment applies ONLY to claims that EXCEED the
  original ported SI. It does NOT restrict claims within the original SI.
- Example: Ported ₹{ported_SI} → Increased to ₹{total_SI} at renewal.
  Fresh {X}-month waiting applies only to the ₹{increment} increment.
  Claims up to ₹{ported_SI} are fully active immediately.

EDGE CASE — INSURER APPLIES CONDITION-SPECIFIC EXCLUSION ONLY:
In some ported policies, the insurer confirms that the full enhanced SI is active
immediately, with the fresh waiting period applying ONLY as a named condition
exclusion — not as an SI cap on the increment.

When personal_waiting_periods contains a named condition with a fresh wait,
treat it as a CONDITION EXCLUSION, not an SI restriction:
- total_effective_coverage = full current SI
- DO NOT write "claims above ₹{ported_SI} are capped for this condition"
- DO NOT write "the ₹{increment} increment has a {X}-month wait"
- INSTEAD write:
  "Full ₹{total_SI} is available for all conditions. [Condition name] is excluded
  until [end_date], after which the full ₹{total_SI} applies to it as well."

key_failure_points entry MUST be written as:
✓ "[Condition name] not covered until [end_date]. All other claims: full ₹{total_SI} active."
✗ "Enhanced ₹{increment} portion has a {X}-month wait for [condition name]." (FORBIDDEN)

RULE 3 — MANDATORY LANGUAGE FOR SUMMARIES AND VERDICT:
WRONG (NEVER WRITE THIS):
✗ "Your ₹{total_SI} policy has a waiting period."
✗ "The newly added ₹{increment} will have a wait for conditions."
✗ "Note that while your base ₹{ported_SI} cover is active, the ₹{increment}
   has a wait for that specific issue." — THIS IS MISLEADING. Reframe correctly.

CORRECT (ALWAYS WRITE THIS):
✓ "Your full ₹{total_SI} cover is active for most conditions. The ₹{increment}
   added at last renewal is subject to a {X}-month specific disease waiting period
   expiring on {end_date}. Claims up to ₹{ported_SI} for any condition are unrestricted."

RULE 5 — PERSONAL EXCLUSIONS: SCOPE AND BADGE LOGIC:

SCOPE RULE:
Personal condition-specific waiting periods apply ONLY to that named condition.
They do NOT restrict any other condition or the overall cover amount.

WRONG: "Your policy has coverage limitations."
CORRECT: "[Condition name] has a {X}-month condition-specific waiting period
          expiring on {end_date}. All other conditions are unrestricted."

BADGE LOGIC — THREE STATES:
For every entry in personal_waiting_periods, determine badge using WORST CASE:

STATE 1 — ✅ Served:
  ALL portions of cover (original + incremental if ported) have completed
  the waiting period for this condition.
  → is_active_today = false

STATE 2 — ⚠️ Partial:
  The waiting period is served on the original/base SI, BUT an active fresh
  waiting period exists on an incremental SI amount for this same condition.
  → is_active_today = true
  → message = "Served for original ₹{ported_SI} cover. Fresh {X}-month wait on
    incremental ₹{increment} active until {end_date}."

STATE 3 — ⏳ Active:
  Waiting period is active across the full cover for this condition.
  → is_active_today = true
  → message = "Wait {X} more months. Coverage for this condition begins
    on {end_date}."

RULE: If ANY portion of the cover has an active waiting period for a
condition → is_active_today = true. NEVER mark ✅ Served unless
ALL portions are clear.

RULE 6 — total_effective_coverage FIELD (MANDATORY):
Always populate coverage_structure.total_effective_coverage with the FULL current SI
including all increments. This is the number that will display on the frontend as
"Effective Cover." Never set it to only the ported portion.

Example: Ported ₹{ported_SI}, increased to ₹{total_SI} → total_effective_coverage = {total_SI}.
